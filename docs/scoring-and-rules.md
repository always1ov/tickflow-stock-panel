## ⚠ 先说结论: 评分系统本身没有问题, 通道延申也没有拖后腿

用户的担心:「你不能全废了我上一版本的评分系统, 量化通道的延申只是为了完善
评分系统」。**梳理的结论正好相反, 而且是量出来的**:

**① 通道延申真正进分的只有三个量, 一个都不建议动:**

| 进分的量 | 去哪 | 权重 |
|---------|------|------|
| `spread` 三线间距 | 质地轴 | 0.15 |
| `accel` 加速度 | 时机轴 | 0.15 |
| `compress_days` 压缩天数 | `base` 的时长那一半 | 名义 8.5%(实际更低, 见 §5) |

**② 这两个恰恰是全系统区分度最好的因子** —— 实测 600 次随机游走:

    spread_score   p10~p90 = 87 分   ← 最宽
    accel_score    p10~p90 = 79 分   ← 第二宽
    把握分(合成)   p10~p90 = 17 分

也就是说, **通道延申不但没有稀释评分系统, 它是目前撑起区分度的那一部分。**
R195 把它们加进来这个决定, 事后看是对的。

**③ 第 6 节里被标成"有问题"的三个, 全都不进分 —— 有硬证据:**

```
opportunity_score.py 全文里出现 'baseline': False   'energy': False
把握分 原样            86
把握分 baseline 置空   86     ← 一分不差
把握分 baseline 塞垃圾 86     ← 一分不差
```

- `baseline()` 匀速基准 —— 只在组合表弹窗显示一句话
- `band_energy` 频段能量 —— 只在复盘弹窗显示 + 落台账
- `_VERDICT_SCORE` —— **零引用的死代码**(v1 遗留, 那时候通道结论真的加减分)

**把这三个全删掉, 任何一只票的把握分都不会变一分。** 它们是"说给人听的话",
不是"算分的料"。§6 说的"宁可只保留 100% 正确的"针对的是**这三句话**,
不是评分系统, 也不是 `spread`/`accel`。

**④ 门槛、两轴、几何平均、倒 U 曲线、置信系数 —— 一条都没建议改。**
§7 的 P0/P1 里没有任何一项动打分口径。

## 0. 一句话结构

    第 0 层  硬门槛     四条,  否决制,  不打分     → 有没有资格被看
    第 1 层  两轴打分   质地 × 时机, 几何平均      → 排第几
    第 2 层  注记       挂着给人看, 一分不加不减   → 看到它时该知道什么
    第 3 层  展示筛选   门槛分 + 条数 + 保底       → 今天摆哪几只出来
    第 4 层  判定       该动了 / 怎么办            → 决策台那两行

**打分层与判定层是两套独立的东西**, 只共享原料不共享结论: 把握分不进
「怎么办」, 「该动了」也不进把握分。

## 1. 计算流程

一次今日总览请求, 机会区这条链走七步:

| 步 | 在哪 | 做什么 |
|----|------|--------|
| ① 收候选 | `score_opportunities` 路 A/B + `coiling_candidates` 路 C | 三条路取并集 |
| ② 备原料 | `_build_overview` | 只给候选票批量取 量能/通道/门槛原料 |
| ③ 过门槛 | `osc.check_gates` | 四条硬否决, 被挡的只计数不进列表 |
| ④ 算因子 | `osc.score_candidate` | 10 个因子各自映射到 0~100 |
| ⑤ 合成 | `_blend` → 几何平均 → × 置信 | 两轴各自加权 → √(质地×时机) → 打折 |
| ⑥ 排序 | `out.sort` | 分降序 → 数据齐全优先 → 质地高优先 → 代码 |
| ⑦ 筛选 | `filter_opportunities` | 板块 → 门槛分 → 保底 → 截断 |

### 候选三路(取并集, 先命中的定 `kind`)

| 路 | 触发条件 | 新鲜度取值 | 备注 |
|----|---------|-----------|------|
| A 六态转强 | `signal ∈ {转多, 回升}` | `FRESH_CURVE(duration)` | 唯一有真实"第几天"的一路 |
| B 逼近买点 | AI 看多 且 `0 ≤ (触发价−现价)/现价 ≤ 2%` | 固定 `82` | 突破还没发生 |
| C 通道酝酿 | `phase ∈ {coiling, launching}` 且六态多头 | 固定 `55`(中性) | 不依赖当天信号, 熊市兜底 |

A 与 B 同时成立时**取更高的新鲜度**, 不因"信号已第 4 天"抹掉"马上到价"。

## 2. 数据来源

| 因子 | 来源 | 口径 |
|------|------|------|
| `template` | `trend_template.assess(closes, rs6)` | 八条模板, **八条全判得出才计入** |
| `base` | `trend_rhythm.assess` + `runs.compress_days` | 档位六成 + 天数四成 |
| `rs` | `ret_20d − bench_ret_20d` | 百分点 |
| `state` | `livermore` 六态 | UT/NR/SR 三档 |
| `spread` | `keltner_geometry.geometry` | `(MA20−MA120)/ATR`, 带符号 |
| `fresh` | 六态 `duration` 或路 B/C 的固定值 | 天 |
| `pos` | `keltner` 短期通道位置 | 0~1(轨外越界) |
| `vol_ratio` | 盘后快照 | 量 / 5 日均量 |
| `turnover` | 盘后快照 | % |
| `accel` | `geometry.accel.a1` | ATR/天 |

**全部冻在收盘口径。** 盘中实时(`live`)单独一份, 一分不进评分 —— 用户的用法
是"决策看收盘、盘中一直盯着"。

## 3. 权重全表

```
质地轴 QUALITY_WEIGHTS            时机轴 TIMING_WEIGHTS
  template  0.34                    pos        0.272
  base      0.2125                  fresh      0.2635
  rs        0.17                    vol_ratio  0.221
  state     0.1275                  accel      0.15
  spread    0.15                    turnover   0.0935

把握分 = √(质地 × 时机) × 置信
置信   = (覆盖率_质地 × 覆盖率_时机) ** 0.25
```

老四项的**相对**比例是从 R134 旧权重推出来的(不是重编), R195 加入
`spread`/`accel` 时把老四项按 0.85 精确缩放, 保住了这个性质。

**缺数据 → 权重让给还在的因子, 再乘置信系数打折。**
「你关掉的」与「我们没读到的」分开: 关掉的压根不进分母, 一分不扣。

## 4. 规则层清单(按优先级)

### 4.1 硬门槛(否决制, `check_gates`) —— **数据缺失一律放行**

| 码 | 条件 | 为什么是门槛而不是扣分 |
|----|------|----------------------|
| G1 `trend_side` | 六态 ∉ {UT,NR,SR} | 逆势的"突破"多半是反弹 |
| G2 `lifeline` | 收盘 < MA20, **或**今天在上而昨天在下 | 连续两日才算, 免得在 MA20 附近反复踢进踢出 |
| G3 `long_down` | 收盘 < MA120 **且** MA120 向下 | 位置+斜率都要, 只用一个会误杀/漏判 |
| G4 `rhythm_failing` | 至少两轮进多头又跌出且低点更低 | 唯一"次数越多越该躲"的形态, 打分压不住 |

四条叠加 = **只做上升趋势中继的早期, 不做底部反转**。这是一个真实且持续
存在的机会成本, 不是可调参消除的。

### 4.2 展示筛选(`filter_opportunities`, 顺序有讲究)

1. 板块过滤 —— **必须在截断之前**, 否则看到的板块机会是残缺的
2. `score ≥ min_score`(默认 60)
3. 保底: 够格的不足 `FLOOR_ROWS=3` 时从排序补齐, 补进来的标 `below_bar`
4. `max_show`(默认 15)截断

「已滤掉 N 只」始终指**没过门槛分**的条数, 与保底补了几条无关。

### 4.3 「该动了」(`watchlist_urgency.assess`, 首个命中即定档)

| 序 | 档 | 条件 | 方向 |
|----|----|------|------|
| ① | `triggered` 已触发 | 出场线已破 | 卖 |
| ② | `near` 逼近 | 离出场线 ≤1.5% | 卖 |
| ③ | `near` 逼近 | 离翻转价 ≤2% | 持有看转弱=卖 / 空仓看转强=买 |
| ④ | `flip` 刚变盘 | 六态 `duration == 1` | 多头=买 / 空头=卖 |
| ⑤ | `band` 到轨 | 短期通道贴/破上下轨 | **看趋势 + 看另外两档**(见下) |
| ⑥ | `idle` 无事 | 其余 | 中性 |

第 ⑤ 档 R212/R214 两轮修过, 现在是四情形 × 通道结构限定:

    到上沿 + 多头 + 三档不偏卖 → 不是卖(沿上沿走是常态)
    到上沿 + 多头 + 三档已偏卖 → 中性(大级别也到上沿了, 那句话不成立)
    到上沿 + 空头             → 卖
    到下沿 + 多头 + 三档不偏卖 → 买(甩人下车)
    到下沿 + 多头 + 三档偏卖   → 中性(三档全下沿 = 不是洗盘)
    到下沿 + 空头             → 不是买(下沿会跟着下移)
    趋势读不到                → 中性

### 4.4 「怎么办」(`stock_playbook.playbook`, 第一条命中即止)

    ① EXIT     出场线已破 —— 不参与讨论
    ② ACT      今天已触发
    ③ CONFLICT 判定打架 —— **刻意排在「逼近」之前**
    ④ WATCH    逼近某个价(near/flip/band)
    ⑤ SHAPE    形态提示(走过头/后劲不足/主升浪/酝酿中)
    ⑥ IDLE     没事

打架规则四条(只认**真正相反**的, 「观望」「无结论」不算):

| # | 条件 | 说什么 |
|---|------|--------|
| ① | 趋势多头 + AI 卖出 / 趋势空头 + AI 买入 | 趋势 vs 模型 |
| ② | 趋势多头 + 通道 `tone ∈ {sell}` | 贵了 |
| ②' | 趋势多头 + 通道 `tone == avoid` | 通道结构比六态先转向 |
| ③ | 阶段 ∈ {走过头, 后劲不足, 下跌中} + AI 买入 | 阶段 vs 模型 |
| ④ | 持有 + 走过头 + 趋势没坏 | 加仓与减仓的理由同时成立 |

> 规则② 在 R214 之前**从写下那天起一次都没触发过** —— 它读 `verdict["side"]`
> (取值 `"high"/"low"`)却拿 `"sell"/"buy"` 去比。已修, 并由
> `test_playbook_combo_matrix.py` 的"每条规则都必须至少触发一次"守住。

### 4.5 持仓档位(`holding_stance`, 顺序即优先级)

    离场  出场线已破
    减仓  趋势转空 → AI 看空 → 距出场线 <1.5% → 到上沿止盈
    加仓  趋势多头 + AI 看多 + 刚转强 + 离线 >5%, 且**没贴上沿**
    持有  其余

止盈减仓排在所有风险驱动的减仓**之后**, 且要求 短中期共振 + 浮盈 ≥10% +
转强已过 2 天 —— 三道闸都是为了防卖飞。

## 5. 规则之间的依赖 / 覆盖 / 冲突

### 依赖

- G2(站上 MA20) ⟹ `pos ≥ 0.5`。**这是恒等式**(短期带以 MA20 为中轴), 所以
  位置因子过门槛后实际取值域只有 [0.5, 1.0+], **有效分辨率是名义的一半** ——
  它在时机轴里 27.2% 的名义权重买到的实际区分度低于 27.2%。
- `state` 同时是 G1 的判据和质地轴的因子 —— **同一个事实投两次票**。
  权重表已经因此把 `state` 压到 0.1275(注释里写明了)。
- 路 C 依赖 `phase()`。R215 让 `launching` 从"永远出不来"变成真能出票,
  **路 C 的出票量因此会上升** —— 这是行为改变, 需要观察。
- `compress_days` 进 `base_score` 的时长那一半, 但**只在 `level == "building"`
  时才真的参与**, 其余情况用中性 50。所以它的实际权重远低于
  `0.2125 × 0.4 = 8.5%` 的名义值。

### 覆盖

- 保底(`FLOOR_ROWS`)覆盖门槛分: 够格不足 3 条时门槛分不再决定显示与否,
  只决定 `below_bar` 标记。**门槛语义没变, 变的是展示策略。**
- `CONFLICT` 覆盖 `WATCH`: 判定打架时不显示"还差 1.2% 到买点"。
- `EXIT` 覆盖一切。

### 冲突(已处理)

- 「到上沿又叫卖」——R212 修(到轨要看趋势)
- 「三档全下沿还叫买」——R214 修(到轨要看另外两档)
- 「下跌中贴下轨叫涨势转弱」——R215 修(阶段要看价格位置)
- 全组合穷举现状: **未标记的买卖矛盾 0 例**(7000 例枚举, 见
  `test_playbook_combo_matrix.py`)

### 冲突(未处理, 见 §7)

- 打分层与判定层可以给出相反的印象: 一只把握分排第 1 的票, 「怎么办」完全
  可能是「先别动」。两层各自都对, 但**页面上没有任何地方说明它们是两套东西**。

## 6. 量化通道延申量 —— 按"有多确定"分级 ★

用户的要求是「宁可只保留 100% 正确的」。按这个标准逐项过:

### A 级 —— 恒等式 / 闭式解, 可放心用

| 量 | 为什么是 100% 的 |
|----|-----------------|
| MA、ATR 从上下轨反推 | `MA=(u+l)/2`, `ATR=(u−l)/(2k)` —— 恒等式, 测试钉死 |
| `d_n = (C−MA_n)/ATR` | 定义。通道位置只是它的线性映射 |
| `spread` | 定义, 带符号 |
| `torn`(≥5) / `nested`(≤1) | 由 `K` 推出的闭式解, 不是拟合 |
| `compress` O | 定义明确; 且 `O = clamp(5−|spread|,0,4)/4`, 与 |spread| 单调对应 |
| `a1 = v1 − v2` 的匀速零点 | **精确成立**(实测 abs < 2e-3), 不是近似 |
| `stack` / `combo_code` | 定义 |
| `runs`(在轨外/压缩连续天数) | 计数 |

### B 级 —— 量本身正确, 但**解释是先验**

| 量 | 正确的部分 | 先验的部分 |
|----|-----------|-----------|
| `spread_score` | spread 本身 | 倒 U 曲线的峰位(2.5)与宽度 |
| `accel_score` | a1 本身 | 峰位 0.12 |
| `phase()` | 分档用的量都是 A 级 | 阈值 1.0 / 3.0 / 5.0 |
| `event()` | 位置×方向×时间的组合 | `MAIN_ADVANCE` 五条 AND 的阈值 |
| `combo_note` | 27 组合是**生成的**不是誊抄的 | 11 条补充文案 |

**这两个恰好是全系统区分度最好的因子。** 实测(600 次随机游走):

    spread_score  p10~p90 = 87 分
    accel_score   p10~p90 = 79 分
    把握分整体    p10~p90 = 17 分

也就是说, 通道延申进分的那两个量**不但没有稀释系统, 反而是撑起区分度的**。

### C 级 —— 有已知缺陷, 建议降级或撤掉

> **再强调一次: 下面三个一个都不进分。** 删光它们, 把握分一分不变(证据见
> 文首「先说结论」③)。它们是界面上的三句话, 不是评分系统的零件。

**① `baseline()` 匀速基准 —— 有 bug, 且 bug 显示在界面上**

`ratio = 实际中期偏离 / 匀速该有的中期偏离`。当短期与中期偏离**方向相反**时
ratio 为负, 而 `ratio < 1 − 0.15` 这一支把它判成「冲在前面 —— 最近这一段
明显比之前快」。

实测(800 次): 判「冲在前面」的 536 例里 **123 例(23%)是这种符号翻转**。样例:

    d短 = −1.3, d中 = +1.5  →  ratio = −0.37  →  「冲在前面」
    实际含义: 刚跌破 MA20 但还在 MA60 之上 —— 回调刚开始, 不是"更快"

而界面(`ComboTableDialog`)把数字和结论并排显示: 「中期该到 −4.0, 实际 1.5
—— 短期已经甩开中期该有的位置」。**数字自己就在打脸结论。**

> 处置建议: `ratio < 0` 时**不给结论**(与 `|d短| < 0.30` 时同一个做法), 或者
> 单列一档「两个尺度还没对齐」。这个量本身(比值形式的加速度)是对的, 错的只是
> 没处理符号翻转这一支。

**② `band_energy` 频段能量 —— 归一化正确, 但那句解释不成立**

归一化本身是对的: 除以 `(9.5, 20, 30)` 之后**纯匀速下三份恰好各 1/3**(实测
`{s:0.333, m:0.333, l:0.333}`), 这一步的推导没问题。

问题在解释。文档写着「短频 > 1/3 = 这一波是消息驱动」。实测 300 次**纯随机
游走**(既无消息也无趋势):

    dominant 分布: s 198 次 / m 54 次 / l 48 次   —— 66% 判"短波动主导"
    share.s 中位数 0.435, 远高于 1/3

原因: 归一化基准是**匀速**, 而真实价格更接近随机游走 —— 随机游走没有趋势,
高通项相对基准天然偏大。于是「几天的短波动」会对三分之二的票、在大多数
时候成立, 「消息驱动」这个读法没有信息量。

> 处置建议: 这个量**不进分**(现在也没进), 只在复盘弹窗显示。**要么撤掉,
> 要么把解释改成中性的事实描述**, 不要说"消息驱动"。若要留, 基准该换成
> 同期全市场的中位数(相对分位), 而不是匀速理论值。

**③ `_VERDICT_SCORE`(today.py:692) —— 死代码, 且长得像在打分**

10 条通道结论配 +10 ~ −15 的分值, **全项目零引用**。它是 v1 的遗留(那时候
通道结论真的加减分)。留着的危害不是占地方, 是**读代码的人会以为通道结论
在参与打分** —— 而现在它是纯注记。

> 处置建议: 删。

## 7. 薄弱点与可优化项

按"该先动哪个"排:

### P0 —— 是错的, 该修

1. **`baseline()` 的符号翻转**(§6-C-①)。23% 的「冲在前面」是错判, 且界面上
   数字与结论自相矛盾。修法很小: `ratio < 0` 时返回 None 或单列一档。
2. **`_VERDICT_SCORE` 死代码**(§6-C-③)。这一轮已经在 `_conflicts` 规则②、
   `PH_LAUNCHING`、`lib/button.ts` 上各栽过一次 —— 同一类问题的第四例。

### P1 —— 不是错的, 但会误导

3. **`band_energy` 的"消息驱动"解释**(§6-C-②)。要么撤, 要么改成中性描述。
4. **`min_score` 这个旋钮几乎没作用**。实测把握分 p10~p90 只有 17 分,
   60 分只挡掉约 1.6% 的候选。名次/分位已经补上了, 但**旋钮还留在界面上**,
   用户以为自己在调筛选强度。要么换成"只看前 N 名/前 N%", 要么标注它的实际
   效果。
5. **路 C 的判定写在两个地方**: `coiling_candidates()` 选票 + `score_opportunities`
   里再判一次同样的条件。现在两处一致(都用 `_COILING_PHASES` + `kg.phase`),
   但这正是 R201 那个 bug 的土壤。应该只留一处。
6. **打分层与判定层没有互相说明**。把握分第 1 的票可以同时是「先别动」。
   两层各自都对, 但页面上没有一句话交代它们是两套独立的东西。

### P2 —— 结构性, 需要数据才能定

7. **所有曲线都是先验, 没有一条被台账反过来验证过。** `score_ledger` 攒了
   数据, 但目前只做展示与 AI 提炼, **没有回流去调曲线**。这是整个系统最大的
   开环: 十个因子的形状全靠推理。优先该验的三个:
   `SPREAD_CURVE` 的峰位、`FRESH_CURVE` 第 1 天还是第 2 天最高、
   `MAIN_ADVANCE` 那五条 AND。
8. **`MAIN_ADVANCE` 是五条 AND**, 任一条不满足就整个降级。五个先验阈值串联,
   命中率会很低而且脆 —— 值得改成计分制(五条中几条)再定档。
9. **`compress_days` 的名义权重与实际权重差很多**(只在 `building` 时生效)。
   要么让它无条件参与, 要么把这个条件写进界面的权重说明里。
10. **G2 与 `pos` 因子信息重叠**(恒等关系, §5)。代码注释已承认这一点。
    可选项: 把 `pos` 曲线的定义域改成 [0.5, 1.25] 上重新铺开, 把浪费掉的
    那一半分辨率拿回来。

### 不算薄弱点、但要有心理准备的

- 四道门槛叠加 = **只做上升趋势中继的早期, 不做底部反转**。底部反转的第一波
  必然错过。这是设计取舍, 不是可调参消除的缺陷。
- 「平均」这件事本身就把取值挤向中间, **因子越多挤得越狠** —— 实测纯随机
  满量程因子跑同一套合成也只有 24 分带宽。这是数学性质, 不是曲线锚点的锅。
  R204 的因子开关(少平均几个)是对症的解法。
